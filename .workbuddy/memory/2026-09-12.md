# 2026-09-12

## 哈基米生活记录器（Web 高保真原型）

从零搭了一个可交互原型，覆盖用户提出的全部模块：登录、人/角色体系、五大记录器、等级与四值、成就勋章、曼波换装、社区与榜单、意见反馈、规划中的未来模块。

关键决策：
- 交付形态：可点的高保真 Web 原型（用户选择），纯前端，无构建步骤。
- 等级上限：10 级（用户拍板，我建议 12 级未被采纳）。
- 数据：用户选择了「接入云端数据库」，但随后在开通确认弹窗中拒绝（declinedByUser + useLocalImplementation=true），因此改为 localStorage 持久化。数据层 `js/store.js` 全部接口为 async 并集中在此文件，将来接服务端只改这一个文件。
- 脚本形态：最初写成 ES Modules，但本地 HTTP 预览被代理拦截（127.0.0.1 返回 502），为保证双击 index.html 即可运行，改为经典脚本 + `window.HJ` 命名空间，按依赖顺序在 index.html 中加载。

踩过的坑：
- 并行对同一文件发多次 Edit 会出现「返回成功但未写入」，改完后必须 Grep/Read 复核。
- `export ` 批量替换为 `function ` 时，`export async function` 会变成 `function async function`，需再修正。
- 业务 bug：睡眠的「正常」状态 key 是 `good` 而非 `normal`，导致额外值与「完美一日」成就永远不发放，已用 `isNormal(type, status)` 统一处理。

文件结构：`index.html`、`css/app.css`、`js/{config,store,audio,ui,ctx,page-login,page-home,page-mambo,page-community,page-me,app}.js`。所有数值、等级名、勋章、哈基米台词集中在 `js/config.js`。

待办（用户明确列为「未来」）：抽奖、分享海报、五款小游戏、桌面小组件、位置/轨迹共享、亲友关联、交友、App 使用记录、手机状态、通话/锁屏截屏、待办事项、真实 OCR 外卖识别、真实服务端与账号体系。
